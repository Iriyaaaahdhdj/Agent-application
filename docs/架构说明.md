# 架构说明

## 目标

项目目标是把课程资料、用户问题、大模型回答和学习报告串成一个可复用的学习助手流程。当前版本保持 CLI 形态，优先验证核心链路稳定性。

## 主流程

```text
用户问题
  -> 参数解析
  -> 资料读取
  -> 文本清洗
  -> 豆包 API 调用
  -> JSON 字段归一化
  -> Markdown 报告生成
  -> 本地保存
  -> 飞书通知或 mock 预览
```

## 模块职责

| 模块 | 责任 |
|---|---|
| `main.py` | CLI 参数解析、课程资料读取、模型调用、报告生成 |
| `feishu_notify.py` | 从报告提取摘要，并发送飞书通知或 mock 预览 |
| `data/sample_course_notes.md` | 默认课程资料样例 |
| `data/eval_cases.csv` | 问答评测集和人工复核记录 |
| `scripts/evaluate_cases.py` | 汇总评测指标和 badcase |
| `scripts/smoke_test.py` | 离线自检核心纯函数 |
| `docs/大模型评测报告.md` | 评测设计和口径说明 |

## 设计取舍

### 保留 CLI

当前项目先保留 CLI，是为了让核心链路足够清楚：输入、处理、输出都能被快速复现。网页界面可以作为后续扩展，但不应该掩盖核心逻辑。

### 使用 JSON 输出

模型输出被要求为 JSON，再由程序生成 Markdown 报告。这样做有两个好处：

- 报告结构稳定，便于后续接入网页、数据库或通知系统。
- 可以对字段进行归一化处理，降低模型偶发漏字段导致流程中断的风险。

### 引入评测集

评测集不是为了追求绝对分数，而是为了持续发现问题。当前重点观察：

- 回答是否围绕课程资料
- 资料缺失时是否标注边界
- 指定格式任务是否稳定
- 不同 Prompt 版本是否真的改善体验

## 后续扩展

| 优先级 | 方向 | 说明 |
|---|---|---|
| P0 | 资料片段引用 | 将资料分段编号，回答中输出依据片段 |
| P0 | 格式校验 | 对 JSON 输出增加 schema 校验和失败重试 |
| P1 | RAG 检索 | 按问题召回相关资料片段，减少整篇资料塞入 Prompt |
| P1 | 反馈记录 | 记录用户是否觉得回答有用，以及失败原因 |
| P2 | Web 页面 | 支持资料上传、提问、报告预览和历史记录 |
